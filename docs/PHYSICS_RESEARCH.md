# 小海捏捏 · 真正的黏弹性胶体（物理核心评估 / 实验路线）

2026-10-15 · 寒枝研究草案 · **实验分支**：`experiment/viscoelastic-material-2d`

## 先纠正核心错误

当前主线的 200×200 高度场只表示一张单值表面；再把“拉丝”作为独立对象绘制，不是把胶体本身提起来。同样，单纯让拉丝与盆体颜色一致，甚至用同一着色器做一个平滑并集，也不能代替真实的物质传递。

**新引擎唯一真源必须是持续存在的物质粒子（位置、速度、质量和连接）。** 渲染器只能读取粒子状态重建表面，不能再凭空添加胶体。所有效果——按压、揉捏、提拉、松开、颈缩、断裂、回流、重新粘连——都发生在同一组粒子上。

## 关键技术裁决

- 选择 **Clavet 风格的 SPH 粒子 + 双密度松弛 + 动态黏弹连接** 作为第一个可交互验证内核；CPU 使用固定步长、空间散列、手指锚点约束；小规模即可显著验证是否真的拉起粒子。
- 移除“单独绘制的提拉丝 / 拉伸体积账”作为权威运动学来源；只有粒子坐标和质量决定物体是否存在。
- 第一步是**独立二维剖面物理实验台**，用以确认粒子被抓住、连续牵动、颈缩、回流与物质数量不变。二维演示不能冒称成完成的 3D 小海。
- 第二步将求解器升级为 3D 或 2.5D 的粒子厚度模型，抓点真正位于三维世界空间；采用 WebGL2 密度纹理 / 表面重建，或 WebGPU 并提供兼容性后备。
- 最后才把现有的透明盒子、海豚、星星、猫爪、音效迁回：贴饰物必须绑定物质粒子或物质局部坐标，不能直接固定在背景。
- 手机设备优先考虑稳态帧率和发热，而非桌面百万粒子演示。WebGPU 可作为高性能路线，但不以“所有手机天然支持”为前提。

## 验收（不能只拍美图）

1. **同一物质**：指定一批粒子，拉前拉后 ID 和总质量不变；夹起处的粒子确实离开盆中。
2. **力传递**：提拉时附近粒子顺势上移，下面真实出现形变、颈缩与空缺；不能在画面外凭空添加丝。
3. **速度依赖**：慢拉能延展，快拉能更早颈缩/断裂；黏性、弹性参数变化在物理数据层可测。
4. **回流/再粘连**：松开会受重力和弹性恢复；两块重新接触后逐渐结合。
5. **交互**：多触点分别施力；不触碰装饰时移动粒子不会消灭装饰；边界稳定。
6. **自动化**：静置沉降、提拉、松开、质量不变、NaN/越界、碰撞、性能基准。
7. **视觉**：透明果冻的厚度、润湿边缘、折射/高光由物质场法线得到，不增加独立拉丝图层。
8. **兼容**：iPhone Safari 实机操作、移动端连续 2 分钟无严重掉帧/内存膨胀；设定分档运行。
